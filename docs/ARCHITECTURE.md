# Устройство студии

Это один репозиторий с независимыми частями, без обязательного сервера.

- `src/core`: типы проекта, пиксельные операции, генератор палитр, история, стартовые задачи и собственные демо-рисунки.
- `src/store`: состояние редактора и транзакционное сохранение в IndexedDB.
- `src/io`: проверка схем, переносимый ZIP, PNG, атлас, игровой пакет.
- `src/ui`: интерфейс, холст, временная шкала, палитры, карта, план, экспорт и руководство.
- `godot/demo/addons/my_game_studio`: самостоятельное дополнение и скрипты опор для 2D/3D.
- `godot/demo/scripts`: ручная игровая логика и процедурные временные материалы.
- `tests`: проверки ядра, браузерные сценарии и реальные экспортные пакеты во временных результатах.
- `server`: описание будущего сервера интеграций. Сейчас серверной программы нет.
- `artwork` и `references`: политика хранения авторских исходников и материалов для изучения.

## Пиксели и кадры

Каждый слой задаётся один раз для ассета. У каждого кадра есть свой RGBA-массив каждого слоя. Дублирование копирует массивы. Изменение порядка, прозрачности или видимости слоя действует на все кадры; сами пиксели остаются раздельными.

Структура нормализована: объекты адресуются UUID, порядок хранится отдельно. История сохраняет изменения свойств и участков массивов, а не полные снимки проекта на каждый шаг. Для вычисления изменений используется временный снимок операции. Это оставляет компромисс по пиковому потреблению памяти на очень больших проектах; лимиты заданы явно.

Одна операция начинается на нажатии указателя и заканчивается при отпускании или потере захвата. Рисование соединяет точки алгоритмом Брезенхэма. Координаты исходного изображения вычисляются из CSS-координат, масштаба и смещения; плотность экрана влияет только на буфер отображения.

Проигрывание использует время, а не число вызовов таймера. Длительность кадров задаётся в миллисекундах; скорость анимации — множитель. Неподдерживаемые направления остаются пустыми до добавления кадров.

## Сохранение

База `my-game-studio` имеет хранилища `projects`, `cels`, `settings`. Описание проекта и бинарные данные сохраняются в одной транзакции. Записи одного проекта удаляются и заменяются внутри этой транзакции; другая мастерская не затрагивается. Очередь сохранений предотвращает запись старого снимка после нового.

В статусе отражается завершение транзакции. При ошибке работа остаётся в памяти. Граница ответственности браузера: очистка профиля и данных сайта удаляет локальные проекты. ZIP — переносимая резервная копия.

Восстановление ZIP строит отдельную проверенную модель. Открытие происходит только после проверки схемы, связей, размеров и PNG. Проект получает новый UUID записи, ассеты сохраняют свои UUID.

## Публичные интерфейсы

- Модель `Project` и `Asset` в ядре — редактируемое состояние приложения.
- `projectArchive` / `importProjectArchive` — перенос редактируемых данных.
- `assetMetadata` / `gameFiles` — обменный пакет v1.
- `Importer.import_package(path, slot)` в Godot возвращает `{ok, message, id?, directory?}`.
- Автоматически создаваемые ресурсы отделены от ручной сцены и её скриптов.

Перед изменением формата поднять версию и добавить миграцию и проверки совместимости. Не обновлять сохранённые рисунки молча вслед за палитрой. Не считать миниатюру источником данных.
