# GitHub, публикация и будущий ИИ

## GitHub

Основной репозиторий — https://github.com/sunakle/my-game-studio. Он публичный. В поставку входят код, документация и собственные процедурные примеры. Пользовательские проекты остаются в браузере.

`.gitignore` исключает зависимости, сборку, браузерные результаты, `.env`, архивы рисунков, приватные исходники, `.godot` и автоматически импортированные игровые ресурсы. Не добавляйте референсы и тяжёлые оригиналы через принудительное включение. Git LFS пока не нужен: в репозитории нет крупных бинарных исходников.

Для ручной разработки:

```powershell
git status
git add src docs godot tests scripts package.json package-lock.json
git diff --cached
git commit -m "Описание выбранного изменения"
git push origin main
```

Сначала просмотрите список и содержимое выбранных файлов. Коммит после каждого штриха не нужен. Изменения кода и сохранение рисунков независимы.

При ошибке локального входа GitHub восстановите авторизацию подходящим для вас способом; не вставляйте токены в URL и файлы проекта. Подключение Codex к GitHub отдельно от локального `gh`. Принудительная отправка не применяется.

## Размещение сайта

Клиент собирается командой `npm run build` в `dist`. `.openai/hosting.json` содержит только идентификатор Sites и каталог сборки. Ключи в этот файл не входят. Публикация настроена с доступом только владельцу; доступ к GitHub-коду и доступ к сайту — разные настройки.

Локальный адрес и опубликованный адрес имеют разные базы IndexedDB. Облачного хранения рисунков и автоматической синхронизации нет. При переносе используйте редактируемый ZIP.

## ИИ и локальный мост — следующий этап

Сейчас API-провайдер не выбран, серверного API нет, платных запросов нет. Перед его реализацией сверить актуальную официальную документацию выбранного провайдера.

План сервера: отдельный Node.js/TypeScript-процесс; модель задаётся настройкой сервера; ключи хранятся только в переменных окружения без префикса `VITE_`. Редактор не зависит от сервера. Запрос отправляется только по кнопке с явно выбранным ассетом, палитрой и задачей. Предложения сначала показываются, применение — отдельная отменяемая операция.

Мост Godot ограничивается выбранной папкой проекта, одноразовым согласованием пары и проверяемым состоянием соединения. Произвольное выполнение команд не предусматривается. До этого этапа используется файловый ZIP-обмен.
